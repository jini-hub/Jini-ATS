# K-ATS Studio

한국형 채용관리 및 ATS(Applicant Tracking System) 웹 애플리케이션

> **현재 버전: v1.2.0**

K-ATS Studio는 국내 기업의 실제 채용 프로세스를 고려하여 제작한 웹 기반 채용관리 시스템입니다.

채용공고 관리부터 지원자 관리, 이력서 PDF 파싱, AI 기반 지원자 분석 및 ATS 평가까지 하나의 화면에서 처리할 수 있도록 구성하고 있습니다.

---

## 1. 주요 기능

### 채용공고 관리

* 채용공고 등록
* 채용공고 수정
* 채용공고별 채용 상태 관리
* 채용공고별 JD 관리
* 공고별 지원자 연결
* 채용 현황 대시보드

### 지원자 관리

* 지원자 등록
* 지원자 정보 수정
* 지원 단계 관리
* 경력연수 관리
* 학력 관리
* 보유 스킬 관리
* 이력서 원문 관리
* 경력 요약 관리
* 지원자별 ATS 점수 관리

### PDF 이력서 파싱

PDF 이력서를 업로드하면 이력서 내용을 자동으로 추출합니다.

파싱 대상:

* 이름
* 이메일
* 전화번호
* 총 경력연수
* 학력
* 보유 기술 / 역량
* 경력사항
* 이력서 요약
* 주요 강점
* 우려사항

PDF.js를 이용하여 PDF의 텍스트를 추출하고, Gemini API를 이용하여 추출된 이력서 내용을 구조화합니다.

## 2. PDF 파싱 처리 구조

현재 PDF 파싱은 다음과 같은 구조를 사용합니다.

```text
이력서 PDF 업로드
        ↓
PDF.js
        ↓
PDF 텍스트 및 레이아웃 추출
        ↓
기본 정보 1차 추출
        ↓
Gemini API
        ↓
이력서 구조화 분석
        ↓
JSON 데이터 정규화
        ↓
지원자 입력폼 자동 반영
        ↓
지원자 저장
```

단순히 PDF 전체 텍스트를 한 줄로 합치는 방식이 아니라 PDF 내부의 위치 정보를 이용하여 가능한 한 원래의 줄 구조를 유지하도록 개선하고 있습니다.

이를 통해 다음과 같은 문제를 줄이는 것을 목표로 합니다.

* 이름이 다른 텍스트와 섞이는 문제
* 경력사항 순서가 뒤섞이는 문제
* 학력 정보가 잘못 인식되는 문제
* 이메일/전화번호 인식 실패
* 2단 구성 이력서의 텍스트 순서 오류
* 표 형태의 이력서 정보 손실

# 3. Gemini AI 연동

K-ATS Studio는 Gemini API를 이용하여 이력서 PDF를 분석합니다.

HTML 내부의 API Key 설정값을 통해 Gemini API를 사용할 수 있습니다.

```javascript
const GEMINI_API_KEY = "여기에_API_KEY_입력";
```

API Key를 입력한 후 별도의 서버 없이 브라우저에서 직접 Gemini API를 호출하는 구조입니다.

### 현재 처리 방식

```text
PDF 업로드
   ↓
PDF.js 텍스트 추출
   ↓
추출 텍스트 생성
   ↓
Gemini API 요청
   ↓
JSON 형태의 이력서 분석 결과
   ↓
지원자 입력폼 자동 입력
```

Gemini에는 다음과 같은 정보를 요청합니다.

```json
{
  "name": "",
  "email": "",
  "phone": "",
  "years": 0,
  "education": "",
  "skills": [],
  "resumeSummary": "",
  "careerSummary": "",
  "highlights": [],
  "concerns": []
}
```

AI가 반환하는 값은 다시 프로그램에서 정규화하여 잘못된 데이터 형식이 입력되는 것을 방지합니다.

# 4. API Key 설정

현재 구조에서는 `index.html` 내부의 다음 부분을 수정합니다.

```javascript
const GEMINI_API_KEY = "";
```

예:

```javascript
const GEMINI_API_KEY = "AIzaSyXXXXXXXXXXXXXXXXXXXXXXXX";
```

API Key를 입력한 후 `index.html`을 저장하고 브라우저에서 다시 열어야 합니다.

### 주의

현재 구조는 **프론트엔드에서 Gemini API를 직접 호출하는 방식**입니다.

따라서 API Key가 HTML 코드에 포함됩니다.

실제 서비스로 배포할 경우에는 API Key를 HTML에 직접 넣는 방식을 사용하지 않는 것이 좋습니다.

향후에는 다음과 같은 구조로 변경하는 것을 권장합니다.

```text
Browser
   ↓
K-ATS Backend
   ↓
Gemini API
```

이렇게 하면 Gemini API Key를 서버 환경변수로 관리할 수 있습니다.

# 5. 현재 데이터 저장 방식

현재 버전은 별도의 서버/DB 없이 브라우저의 `localStorage`를 이용하여 데이터를 저장합니다.

사용되는 저장 키:

```javascript
const STORAGE_KEY = "kats";
```

따라서 현재 데이터는 해당 브라우저에 저장됩니다.

### 장점

* 서버가 필요하지 않음
* 별도 DB 구축 없이 바로 실행 가능
* GitHub Pages 등의 정적 웹 환경에서도 실행 가능
* 개발 및 테스트가 편리함

### 현재 한계

브라우저별 데이터가 서로 공유되지 않습니다.

예를 들어:

```text
PC Chrome
    ↓
지원자 데이터 A

다른 PC
    ↓
지원자 데이터 없음
```

또한 브라우저 데이터를 삭제하면 저장된 데이터도 삭제될 수 있습니다.

# 6. 현재 ATS 분석

지원자의 다음 정보를 이용하여 기본 ATS 분석을 수행합니다.

* 지원 직무
* JD 키워드
* 이력서 내용
* 보유 스킬
* 경력연수
* 학력

기본적인 키워드 매칭 및 경력/학력 요소를 조합하여 지원자별 ATS 점수를 계산합니다.

현재 ATS 점수는 실제 채용 결과를 의미하는 것이 아니라 **채용담당자가 지원자를 빠르게 비교하기 위한 참고 지표**입니다.

# 7. 지원자 데이터 구조

현재 지원자는 대략 다음과 같은 형태로 관리됩니다.

```javascript
{
  id: "",
  job: "",
  name: "",
  email: "",
  phone: "",
  stage: "",
  years: 0,
  education: "",
  skills: "",
  resume: "",
  resumeSummary: "",
  careerSummary: "",
  score: 0,
  rejectReason: "",
  updated: ""
}
```

향후에는 경력사항을 단순한 문자열이 아니라 구조화된 데이터로 관리할 예정입니다.

예:

```javascript
career: [
  {
    company: "",
    period: "",
    position: "",
    department: "",
    description: ""
  }
]
```

이를 통해 회사별 경력 조회와 경력기간 계산을 보다 정확하게 처리할 수 있습니다.

# 12. PDF 파싱의 한계

PDF는 문서마다 내부 구조가 다르기 때문에 모든 PDF에서 동일한 정확도를 보장할 수 없습니다.

특히 다음 유형은 추가적인 처리가 필요할 수 있습니다.

### 이미지형 PDF

텍스트 레이어가 존재하지 않는 스캔 PDF의 경우 PDF.js만으로는 텍스트를 추출하기 어렵습니다.

향후 OCR 기능을 추가할 수 있습니다.

```text
스캔 PDF
   ↓
OCR
   ↓
텍스트 추출
   ↓
Gemini 분석
```

### 복잡한 2단 레이아웃

다음과 같은 이력서는 텍스트 위치에 따라 읽는 순서가 달라질 수 있습니다.

```text
┌───────────────┬───────────────┐
│ 개인정보       │ 경력사항       │
│ 학력           │ 주요 업무      │
│ 연락처         │ 프로젝트       │
└───────────────┴───────────────┘
```

따라서 향후 PDF 영역 분석 및 컬럼 인식 기능을 추가할 수 있습니다.
